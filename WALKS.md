# Тематические прогулки

Прогулка привязана к месту назначения через `Stop.walkId`: её точки и отдельная карта не меняют основной маршрут. У точки отправления редактор прогулку не предлагает. Одна основная кнопка подбирает места и строит карту; после изменения списка эта же кнопка пересобирает прогулку. Гостиницы находятся в отдельном сворачиваемом блоке.

## Источники и ограничения

`WalkThemeService` объединяет OSM и Wikimapia. Поиск ограничен одним запросом одновременно и общим бюджетом 12 секунд. Источники работают параллельно; при задержках возвращается доступная часть результатов. Нельзя гарантировать полноту общественных источников или постоянную доступность за 20 секунд.

OSM: `ni-c/osm-mcp` → Overpass → Photon. Photon возвращает только индексируемые объекты, поэтому не заменяет полный Overpass. Региональные зеркала Overpass могут не покрывать Россию; `OVERPASS_URL` позволяет выбрать подходящий глобальный сервер.

Wikimapia: `box` без параметра категории → предварительный локальный отбор → `place.getbyid` для верхних кандидатов → проверка темы по категориям/описанию → один групповой запрос OSM в радиусе 15 м. Если проверка OSM недоступна, объект не получает неподтверждённую метку «народное место».

Объекты с диагональю `box` больше 300 м исключаются: центр района не является адресом входа или точкой посещения. Некорректные/отсутствующие границы сами по себе не исключают объект. Отрицательные результаты по крупным площадям кэшируются на 30 минут. Отклонённое обогащение нельзя обойти категориями из `box`: непроверенная точка не попадает в прогулку.

Для мистической темы общие категории `historic`/«историческое место» недостаточны. Нужна тематическая категория либо ключевые слова легенды, мистики или заброшенного объекта в описании. Текст источника не гарантирует историческую достоверность легенд.

Ранжирование: совпадение категории 1, совпадение описания 0,5; подтверждённое отсутствие в OSM для Wikimapia +0,5; отсутствие Wikidata/малое число sitelinks у OSM +0,3; открыто +0,2, закрыто −0,2; фото с указанной лицензией +0,1. Закрытые места сохраняются с предупреждением. Совпадения координат и названия объединяются с приоритетом описания Wikimapia и сохранением часов OSM.

Парсер `opening_hours` поддерживает базовые случаи. Неподдерживаемое расписание и отсутствие времени посещения означают `UNKNOWN`. Праздники, билеты и фактическую доступность нужно проверять перед посещением. Sitelinks запрашиваются пакетно и кэшируются минимум на 24 часа.

## Фотографии

Отдельный запрос обогащения: Commons MCP по названию/координатам → Commons geosearch → фото Wikimapia с явной допустимой лицензией. Неизвестная лицензия исключает фото, а не само место. Не более одной фотографии на остановку и 12 на прогулку; сохраняются автор, ссылка на оригинал и лицензия. Доступность MCP/изображений не гарантирована; выдача может быть без фото.

Снимки и описания хранятся в существующем снапшоте, дополнительные данные — в необязательном `Stop.meta`. Старые снапшоты без `meta` остаются совместимыми. PDF строится через общий механизм конструктора, с отдельной картой и номерами фотографий/точек.

## Переменные окружения

| Имя | Значение по умолчанию / назначение |
|---|---|
| `WIKIMAPIA_API_KEY` | Пусто: Wikimapia отключена; секрет только на сервере |
| `WIKIMAPIA_KEY` | Совместимость с локальной конфигурацией; предпочтительно имя выше |
| `CODOC_WALK_MCP_ENABLED` | `false`; включение частного OSM HTTP-моста при деплое |
| `OSM_MCP_ENABLED` | В базовом Compose `false`; мост включает автоматически |
| `OSM_MCP_URL` | В мосте `http://osm-mcp:8000/mcp` |
| `COMMONS_MCP_ENABLED` | `true` |
| `COMMONS_MCP_URL` | `https://gateway.pipeworx.io/commons-wikimedia/mcp` |
| `OVERPASS_URL` | Настраиваемое зеркало Overpass |

Compose передаёт `WIKIMAPIA_API_KEY` как `APP_JOURNEYS_WIKIMAPIA_KEY`. Значение не должно попадать в репозиторий, клиентский JavaScript, Nginx или журнал запросов. Перед развёртыванием проверить наличие секрета в серверном `.env`, сохраняя существующие секреты. Пустой ключ не мешает OSM-only сценарию.

## Запуск MCP

`ni-c/osm-mcp` предоставляет stdio, поэтому он работает в отдельном контейнере через `mcp-proxy` с HTTP `/mcp`. JVM не запускает Node/npx. Зафиксированы `osm-mcp@0.3.2` и `mcp-proxy==0.15.0`. Мост получает только разрешённые инструменты `find_nearby_pois,poi_details`, не получает секреты приложения и не публикует порт наружу.

Из корня, содержащего три репозитория:

```bash
docker build -f ticket-infra/Dockerfile --target osm-mcp -t codoc-osm-mcp .
docker compose --env-file .env -f ticket-infra/compose.api.yml -f ticket-infra/compose.postgres.yml -f ticket-infra/compose.walks.yml up -d osm-mcp
```

Полное обновление: установить `CODOC_WALK_MCP_ENABLED=true` в серверном `.env`, затем `bash ticket-infra/scripts/deploy-postgres.sh`. Скрипт строит последовательно, с резервной копией PostgreSQL и ограничением памяти. Контейнер моста ограничен 256 MiB и 0,5 CPU. Commons использует внешний HTTP-шлюз; свой контейнер не обязателен. Если есть собственный совместимый сервер, задать его HTTP URL в `COMMONS_MCP_URL`.

SDK — `io.modelcontextprotocol.sdk:mcp:2.0.1` с Jackson 2 адаптером, без Spring AI. Для Commons используются реальные инструменты шлюза `commons_wikimedia_search` и `file_info`. Таймауты ограничены, payload и сессии не журналируются.

## Квоты Wikimapia

Один общий ограничитель для старого и нового клиентов: по умолчанию 20 запросов/мин и 5000/сутки, `Semaphore(1)` и минимальный интервал. Это внутренние защитные пределы, а не обещание бесплатной безлимитной квоты: реальные условия аккаунта и ответы провайдера имеют приоритет. Пагинация ограничена временем и оставляет запас для деталей; `max-details-per-request=25` — верхний предел, а не обязательные 25 обращений. При приближении к квоте обогащение прекращается, используются кэш/OSM. Ключ `example` не предназначен для production.

Конфигурация `app.journeys.wikimapia`: `box-page-size`, `max-details-per-request`, `min-description-length`, `quota.minute-limit`, `quota.daily-limit`. Box/details: LRU с TTL 30 минут; cross-check — 24 часа. Нельзя вызывать getbyid для всех объектов bbox или делать отдельный Overpass-запрос для каждого объекта.

## Новая тема

Добавить операторский блок в `app.journeys.walk-themes`; пользовательский ввод не вставляется в Overpass QL:

```yaml
gardens:
  tags: ["leisure=garden"]
  wikimapia-categories: ["garden", "сад"]
  description-keywords: ["ботаничес", "botanical"]
  require-hours: true
```

Для новой темы также добавить локализованный выбор в интерфейсе. Крупные парки текущий лимит 300 м отсекает намеренно: для них нужен отдельный сценарий входов/маршрутов, а не выдача центра территории как остановки.
