# Исторические дома и мистические прогулки

## Источники

`mystic` получает места из локальной таблицы `mystic_places`, без запросов к OSM, Photon или Wikimapia. Встроенный UTF-8 CSV содержит 173 записи из присланных пользователем подборок; повторяющиеся строки и склеенные заголовки удалены. Разные легенды с одинаковыми координатами сохраняются в базе, но в маршрут попадает одна точка на координату. Содержимое — городские предания из пользовательской подборки, а не утверждение о доказанности сверхъестественных явлений. Ссылки ведут на указанные источники.

`bars`, `religious`, `cultural` сохраняют прежнюю цепочку источников. После подбора их описания дополняются доступными сведениями о здании из `building_history`. Названия года, архитектора и стиля переведены на девять языков.

На фронте в отдельной прогулке есть тема **«Исторические дома»**. Можно искать адрес, архитектора или стиль, выбирать дома, видеть их на альтернативной карте Яндекса и создавать отдельную прогулку. Историческая справка сохраняется в описаниях точек и попадает в PDF через существующий механизм документа.

## HOITH: фактическая структура файла

Публичный файл: <https://disk.yandex.ru/d/6rI165UaOpvG0A>.
Проверен скачанный **на сервере** GeoPackage: 1 801 277 440 байт, 3 550 042 объекта, слой `all_cities_181123`, EPSG:3857. В нём нет OSM ID. Импорт использует стабильный идентификатор `hoith:<слой>:<fid>`, преобразует геометрию в EPSG:4326 и читает реальные поля `r_year_int`, `r_adress`, `r_architect`, `r_style`, `r_mkrf`, `r_url`.

Исходный файл не помещается в Git и не скачивается на рабочий компьютер. Скачать на сервере из каталога `/home/ticket/codoc`:

```bash
bash ticket-infra/download_hoith.sh ./data/imports
```

Скрипт получает подписанный URL через API публичных ресурсов Яндекс.Диска, проверяет свободное место, размер и структуру SQLite, затем переименовывает `.part`. Готовый файл сохраняется. Подписанная ссылка в журнал не выводится. `download_hoith.ps1` предоставлен для других машин с достаточным местом; на текущем компьютере его не запускать.

## Импорт и ресурсы

PostgreSQL 17 должен содержать PostGIS. Compose использует `postgis/postgis:17-3.5-alpine`, сохраняя прежний major PostgreSQL, Alpine и том данных. `deploy.sh` через `scripts/deploy-postgres.sh` применяет обе SQL-миграции до старта приложения. Миграции идемпотентны. Географический GiST-индекс мистических точек соответствует выражению запроса `ST_DWithin`, расстояния измеряются в метрах.

До резервного копирования и остановки стека PostgreSQL запускается с `--no-recreate`: захваченный ID контейнера остаётся действительным даже при смене образа в Compose. Новый образ применяется после сборки. При сбое до миграций скрипт сначала поднимает существующую службу БД и затем восстанавливает клиентов. После установки PostGIS откат приложения должен сохранять PostGIS-совместимый образ PostgreSQL 17; обычный образ без библиотек расширения не является заменой для такой базы.

Настройки в `.env`:

```dotenv
HOITH_IMPORT_DIR=/home/ticket/codoc/data/imports
HOITH_IMPORT_ON_STARTUP=true
HOITH_BEFORE_YEAR=1945
HOITH_CITIES=
HOITH_REFRESH_ON_START=false
```

По умолчанию автоматический импорт выключен. При включении загружаются здания с известным годом 1000–1945: это база старых домов, без миллионов современных и недатированных объектов. `HOITH_BEFORE_YEAR=0` снимает возрастной фильтр и требует отдельной оценки места на диске. `HOITH_CITIES=Санкт-Петербург,Москва` ограничивает импорт городами; пустое значение оставляет всю страну. Фильтры применяются в SQLite до декодирования геометрий.

GeoTools читает объекты потоково. В памяти одна пачка из 250 зданий; каждая пачка сохраняется отдельной транзакцией через UPSERT. Полный GeoPackage или полный список зданий в память не загружаются. Путь внутри контейнера — `/app/imports/hoith.gpkg`, каталог смонтирован только для чтения. Исходный файл и база занимают место отдельно.

Если HOITH уже присутствует, обычный запуск не импортирует его повторно. Для обновления или возобновления после прерванного импорта включить `HOITH_REFRESH_ON_START=true`; повторные записи обновятся по стабильному ID, а не продублируются. После успешного импорта вернуть `HOITH_IMPORT_ON_STARTUP=false` и `HOITH_REFRESH_ON_START=false`. Загрузка по сети при старте не выполняется.

## CSV

`app.mystic.csv-path` / `MYSTIC_CSV_PATH` принимают `classpath:mystic_places.csv` или `file:/путь/файл.csv`. При пустой таблице импорт выполняется автоматически. Для обновления заполненной таблицы доступен `MYSTIC_REFRESH_ON_START=true`; существующие записи обновляются по имени и координатам, отсутствующие в новом CSV автоматически не удаляются.

Обрабатываются BOM, кавычки, запятые и переносы строк внутри полей. Некорректные координаты, обязательные поля и ссылки приводят к пропуску строки с номером в журнале. Ошибка структуры CSV откатывает импорт. Ограничение — 25 000 строк. Автоматического геокодирования нет.

## API и проверка

```text
GET /api/journeys/routes/places/themed?longitude=30.315&latitude=59.938&theme=mystic&language=ru&maxStops=7
GET /api/journeys/buildings?lon=30.315&lat=59.938
GET /api/journeys/buildings/nearby?lon=30.315&lat=59.938&radiusKm=1.5&limit=7&beforeYear=1945&q=
```

Точечный поиск возвращает 404, если координата не попала в здание; не подставляет произвольный соседний дом. На границе полигона здание находится через `ST_Covers`. `SPB_PASSPORT` имеет приоритет над HOITH. Поиск рядом ограничен 12 результатами и радиусом 3 км; запрос поиска параметризован. Возвращается компактный JSON без сериализации полной JTS-геометрии.

В H2 используется отдельный путь без PostGIS DDL: мистические точки проходят проверку расстояния после ограничивающего прямоугольника; исторические здания — JTS-предикат. H2-поиск зданий ограничен 5000 записями и предназначен для локальных тестов, не для полной базы HOITH.

Для нативного теста SQL нужен отдельный PostgreSQL/PostGIS с именем базы, содержащим `test`: `CODOC_POSTGIS_TEST_URL`, `CODOC_POSTGIS_TEST_USER`, `CODOC_POSTGIS_TEST_PASSWORD`. `PostgisPlacesTest` откатывает данные и DDL транзакции; без этих переменных тест явно пропускается. Проверка H2 не объявляется проверкой PostGIS.

## Подборки по 500 мест

Запрошенное расширение на 1500 новых мест отложено по последнему указанию пользователя, чтобы завершить продукт и импорт исторических домов. В текущую подборку не добавлены выдуманные координаты или обычные дома, названные мистическими ради количества. 173 записи — исходная объединённая подборка, а не 1500 найденных и проверенных новых мест.
