## Wildcard: сертификат подключён, DNS и автопродление требуют завершения

DNS оставлен на `ns1.hosting.reg.ru` / `ns2.hosting.reg.ru`.
В Cloudflare подготовлены A-записи wildcard и Draw.io, но зона там не активна и публичный DNS ими не обслуживается.

После добавления TXT-записи выпущен сертификат `codoc-wildcard` для `codoc.site` и `*.codoc.site`.
Срок окончания: 9 февраля 2027, 12:04:53 UTC.
Включён `/etc/nginx/sites-available/codoc-journeys`, с портом приложения 8080.
Исправлено экранирование регулярного выражения коротких ссылок; `nginx -t` прошёл, Nginx перезагружен.
Проверки с принудительным направлением на локальный сервер и обычной валидацией TLS:
`invite.codoc.site` и `proposals.codoc.site` — HTTP 200, неизвестная короткая ссылка — HTTP 404;
основной сайт и Draw.io продолжают отвечать HTTP 200 по HTTPS.
Оба авторитетных DNS-сервера пока не возвращают wildcard A-запись: публичная доступность
новых поддоменов ещё не подтверждена.

Подготовлен deploy-hook `/etc/letsencrypt/renewal-hooks/deploy/codoc-wildcard-nginx.sh`: после успешного продления этого сертификата он проверит и перезагрузит Nginx.
Это ещё не автоматизация DNS-проверки: для неё требуется доступ к API панели, управляющей текущей DNS-зоной.
Один лишь включённый `certbot.timer` не обеспечивает продление сертификата, выпущенного вручную.

Осталось: добавить A-запись `*` на IP сервера в REG.RU и проверить её публично;
настроить DNS API и проверить `certbot renew --dry-run --cert-name codoc-wildcard`.
