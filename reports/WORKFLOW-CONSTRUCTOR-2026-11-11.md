# Конструктор путей, КП, мобильные экраны и языки

## Как собрать полностью новый путь

1. Войти в CoDoc и открыть **Конструктор клиентских путей** в рабочем пространстве: `/app/workflows`.
2. Создать обычный шаблон документа в редакторе. Добавить поля схемы или плейсхолдеры, например `name`, `client.name`, `amount`.
3. Нажать **Новый сценарий**, задать название и свободный адрес. Занятость адреса проверяется при вводе, без отправки формы.
4. Выбрать свой шаблон и нажать **Загрузить поля из схемы шаблона** либо добавить поля вручную.
5. Настроить шаги, порядок полей, подписи и обязательность. Поддерживаются текст, длинный текст, число, дата, email, список вариантов и подтверждение.
6. Сохранить черновик, затем опубликовать. Открыть ссылку опубликованного пути и проверить его как посетитель.
7. Посетитель заполняет форму по шагам и получает PDF. Для него вход в редактор не нужен.

В production ссылка использует поддомен `<адрес>.codoc.site`; локально работает `/s/<адрес>`. Прямой маршрут `/flows/<адрес>` также доступен. Нужны уже описанные wildcard DNS, сертификат и nginx из `ticket-infra/JOURNEY-SITES.md`: приложение регистрирует адрес в БД, отдельный контейнер для каждого пути не создаётся.

## Доступ и публикация

- Авторизованный пользователь управляет своими сценариями. Сервер проверяет владельца, включая принадлежность выбранного шаблона.
- Администратор назначается через `WORKFLOW_ADMIN_USER_IDS` — список реальных ID пользователей через запятую в `.env`. Самостоятельная регистрация административных прав не даёт. Переменная передаётся контейнеру приложения.
- Администратор может публиковать общие сценарии в каталоге и управлять ими. Обычный пользователь видит общие опубликованные пути как готовые сервисы.
- Черновик закрыт. Публикация сохраняет отдельную копию формы и макета. Правки исходного шаблона и черновика не меняют опубликованную форму до новой публикации.
- При конфликте версий сохранение отклоняется. Если форма обновилась во время заполнения, сервер предлагает открыть актуальную версию.
- Общий реестр адресов защищён первичным ключом БД: обычный сайт и профессиональный сценарий не могут занять один поддомен.

Движок декларативный: новый сценарий формы → собственного PDF не требует добавления Java enum или отдельного приложения. Произвольные скрипты, новые платёжные провайдеры, рассылки и внешние интеграции через конфигурацию не исполняются: для них нужны отдельные проверяемые обработчики. Сложные повторяемые таблицы остаются возможностью специализированных сценариев, например КП.

## КП

- Страница и PDF получают один макет, а не две независимые вёрстки.
- Обновлены шапка, таблица, чередование строк, выравнивание чисел, итог и колонтитулы. Длинные названия переносятся внутри позиции; позиции переходят на следующие страницы с повтором заголовка таблицы. Итог печатается один раз.
- Список редактора показывает по 10 позиций, поддерживает поиск по названию/номеру, фильтр ошибок и переход между страницами. Максимум — 200 позиций.
- Итог и кнопка продолжения закреплены внизу. Прокручивать весь список до кнопки больше не требуется.
- В предпросмотре есть выбор страницы документа. Excel импортируется с выбором колонок; значения вроде `1 250,50` нормализуются перед отправкой, расчёт денег выполняется без ошибок двоичного floating point.

## Мобильные экраны и языки

- Проверяются узкие экраны 320 и 390 px: перенос навигации, поля без горизонтального переполнения, размер элементов управления и нижняя панель КП.
- Проверка адреса запускается после паузы 400 мс; устаревшие запросы отменяются. Сообщения «занят», «зарезервирован», «свободен» и ошибки проверки появляются рядом с полем; публикация недоступна до успешной проверки. Сохраняется проверка уникальности сервером на случай одновременного создания.
- Интерфейс простых путей и конструктора подключён к девяти языкам приложения. Исправлен пробел прежней проверки: она не учитывала строки, которые вообще не вызывали перевод.
- Смена языка сохраняет незавершённые формы только на время перезагрузки в sessionStorage текущей вкладки; данные посетителя не отправляются на сервер ради переключения языка.
- Даты интерфейса используют выбранную локаль. Пользовательские тексты и содержание собственного шаблона не переводятся автоматически.
- Проверки браузера используют Edge и эмуляцию размеров экрана. Это не проверка физических iPhone/Android и их камер. Для новых строк добавлены машинные переводы; ключевые сообщения проверки адреса вычитаны, полная лингвистическая вычитка носителями языка не выполнялась.

## Развёртывание и ресурсы

`upgrade-workflows.sql` создаёт таблицы сценариев и адресов, резервирует существующие адреса и допускает повторный запуск. Добавлен в production init и `scripts/deploy-postgres.sh` после `upgrade-journeys.sql`. Скрипт сначала делает резервную копию базы. Для PostgreSQL-профиля SQL запускает скрипт развёртывания, поскольку автоматический init в этом профиле выключен.

Новые тяжёлые публичные PDF-запросы включены в общий nginx admission limit и используют существующий `HeavyOperationCapacity`. Новых фоновых воркеров нет. На пользователя ограничено 100 сценариев, 8 шагов и 100 полей; опубликованный снимок макета — до 2 МБ. Списки загружают проекции без больших снимков шаблонов. Ранее заданный бюджет всего стека 2 CPU / 4 ГБ не увеличен.

Изменения выполнены локально. Production, DNS и действующая база не менялись. Полная нагрузочная проверка стека с Docker/PostgreSQL в этой среде недоступна.

## Проверки

- Backend: полный `clean verify` — 159 тестов, 0 ошибок, 1 ожидаемый пропуск нативного OCR. Maven heap 384 MiB, тестовая JVM 768 MiB, два доступных CPU.
- Frontend: полный прогон — 349 тестов в 58 файлах, один worker, Node heap 768 MiB.
- Полный браузерный прогон: 68/68, включая все простые пути, профессиональный конструктор, мобильную ширину, локализацию, редактор, подпись и сохранение данных.
- Четыре сравнения браузера и настоящего PDF: три темы приглашений и многостраничное КП. Для КП остаточное различие 0,45% с учётом сглаживания краёв букв; цвет плоских заливок проверяется по RGB.
- TypeScript, ESLint, зависимости модулей, полнота девяти языков и production-сборка проверены. Для ESLint устранено ненужное создание TypeScript-программ; правила сохранены, типы проверяются отдельно для приложения, unit- и e2e-тестов.
- 18 статических SEO-страниц: уникальные метаданные, canonical, JSON-LD, sitemap и настоящий 404.
- Покрытие контролируемого набора domain/lib: строки 89,09%, ветви 73,88%, функции 95,41%; установленный порог 70% пройден.
- Визуальные фикстуры и шрифты с лицензией сохранены в `ticket-editor/tests/fixtures/journeys`, поэтому проверка из чистого клона не зависит от чужой папки `target`. Обновление — `node scripts/update-journey-fixtures.mjs` после `DocumentFlowTest`.
