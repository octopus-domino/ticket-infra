# Настройки развёртывания стихотворных карточек

Изменения подготовлены локально. На сервер не устанавливались.

## Источники

`compose.api.yml`, оба примера `.env` и генератор нового окружения передают
`APP_POETRY_POEMSHIP_URL=https://poemship.com/mcp` и
`APP_POETRY_POETREE_URL=https://versologie.cz/poetree/api`.
Обязательный ключ PoemShip не нужен. Существующие `.env` не перезаписываются.
В старом H2-сценарии переменные `APP_*` уже передаются контейнеру.

Запросы к источникам выполняет Java-сервис. Добавлять PoemShip, PoetryDB и
PoeTree в браузерную CSP не нужно. Новые контейнеры и фоновые процессы не нужны;
лимиты памяти/CPU для сервера с 2 CPU / 4 ГиБ сохранены.

## Nginx

`nginx.external.conf` по умолчанию использует порт Compose 8090. Для старого
H2-развёртывания установщик подставляет 8080. Порт Compose можно изменить через
`CODOC_HTTP_PORT`; он же передаётся установщику внешнего Nginx.

Установка внешнего конфига включается явно: `CODOC_UPDATE_EXTERNAL_NGINX=true`
в существующем окружении. Скрипт обновляет только уже существующий обычный файл
`/etc/nginx/sites-available/codoc`. Нужны существующие сертификаты, подключённый
сайт и noninteractive sudo. Wildcard-конфиг не заменяется.

Перед остановкой приложения проверяются Compose и параметры окружения.
После проверки работоспособности приложения установщик сохраняет резервную
копию Nginx, проверяет `nginx -t` и выполняет reload. При ошибке восстанавливает
конфиг. Ошибка обновления внешнего Nginx не останавливает уже здоровое приложение.
Оператор должен проверить сообщения об откате, особенно при ошибке самого reload.

В контейнерном Nginx POST `/api/journeys/poetry` включён в существующий общий
лимит тяжёлых запросов. Это ограничение конкурентности, а не платная квота.
