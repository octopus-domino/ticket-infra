# Сверка реализации с ТЗ сервиса маршрутов

Проверено по фазам 0–14, сценариям S1–S11 и критериям приёмки из «ТЗ на сервис маршрутов.html» с учётом уточнения владельца. Построение прогулок, выделение области и поиск POI выполняются в приватном Journey. CoDoc принимает готовый план и привязывает его к выбранному дню поездки.

Исходная точка сверки в Git — редактор `59471f2`, сервер `33779b5`, приватный Journey `10381f1`, инфраструктура `f1c5900`. Производственный деплой приостановлен по указанию владельца.

## Фазы

| Фаза | Реализация | Остаток и приёмка |
|---|---|---|
| 0. Аудит | Инвентаризация в `ticket-pdf/docs/current-state.md`, регрессионный чеклист, флаг `ENABLE_TRIP_PLANNER` для фронта и сервера | Повторить полный набор тестов на одном релизном наборе |
| 1. Домен | Модели выделены в `domain/model`, зависимости проверяет `JourneyArchitectureTest` | Сверить Javadoc и границы классов, оставшихся в прежнем пакете |
| 2. Репозитории | Доменный `TripRepository`, JPA-реализация и тест персистентности; черновики связаны с владельцем | Проверить запись, чтение и разграничение доступа на PostgreSQL целевого релиза |
| 3. Маршрутизация | Единый `RoadRouter` и адаптеры OSRM, BRouter, Valhalla, fallback | Проверить время и геометрию переездов в целевой среде |
| 4. POI | `PoiSource`, адаптеры и `AreaSearchCoordinator` с тестами; интерфейс выбора области работает в Journey | Проверить все требуемые способы выделения и мобильные жесты в Journey |
| 5. PDF | Часть инфраструктуры вынесена, существующие шаблоны и тесты сохранены | Прогнать полный набор старых документов и визуально принять новые |
| 6. Прикладные сервисы | Выделены сервисы конструктора, печати и публикаций; есть ADR по границе персистентности | Сверить полноту декомпозиции и Javadoc/Checkstyle. Отдельная история PR по каждой фазе отсутствует |
| 7. v2 и миграция | `TripV1Migration`, снимок для `v1-compat`, сохранение геометрии и ссылок на фото. Локальная проверка чтения и печати старого маршрута | Проверить миграцию и обратную совместимость на копии рабочей БД, включая старые ссылки и 30-дневное окно сохранения v1 |
| 8. Передача прогулки | `PrivateJourneyToTripConverter`. Playwright проверял передачу из реальной сборки приватного Journey в выбранный день с мобильным размером окна | Приёмка на физическом устройстве. Список и карта приватных прогулок принадлежат Journey |

Поставщики | Яндекс Расписания, курсы Банка России, адаптер Nominatim, собственный MCP каталога Островка и чтение нормализованной выгрузки Росаккредитации | Продакшен-настройки Яндекса и Nominatim, реальная выгрузка реестра, цены и доступность отелей на даты; проверить отказоустойчивость и ограничения запросов |
| 11. Веб | Локальный черновик, сохранение владельцем, контроллеры черновика, городов, отелей и курсов; валидация длительности поездки | Сверить единообразие ошибок и доступность старых эндпоинтов после обновления |

## Сценарии карты

| ID | Текущий результат |
|---|---|
| S1 | Привязка города к точке карты есть. Общее меню карты поездки с созданием сущности по клику остаётся открытым. Точки прогулки выбираются в Journey |
| S2 | Работа с POI прогулки выполняется в Journey. Сквозная приёмка карточки и добавления в день остаётся открытой |
| S3 | Поиск POI по области относится к Journey. Лассо, прямоугольник и радиус требуют отдельной сверки по каждому контролу |
| S4 | Автомобильный переезд можно построить через промежуточные точки. Универсальное преобразование произвольной полилинии в кандидат требует приёмки. Пеший маршрут строится в Journey |
| S5 | Линия переезда открывает карточку с датами и доступными ценой и ссылкой. Проверка отображения обоих местных часовых поясов открыта |
| S6 | Маркер отеля открывает карточку проживания. Поиск отеля и замена используют один редактор проживания |
| S7 | Передача готовой прогулки и её превью проверены. По уточнённому сценарию выбор прогулки выполняется в Journey, результат сохраняется в выбранный день CoDoc |
| S8 | Маркер города перетаскивается, затронутые автомобильные переезды пересчитываются; черновик поддерживает отмену и повтор. Нужен сквозной тест drag → пересчёт → отмена |
| S9 | Линейка поездки измеряет расстояние без сохранения в план. Есть отдельный тест инструмента |
| S10 | Автомобильный переезд собирается в редакторе переезда. Для пешего маршрута пользователь переходит в Journey. Сценарий дорожного построения общественным транспортом остаётся открытым |
| S11 | Кластеризацию при числе маркеров свыше 50, раскрытие кластера и производительность нужно подтвердить. Доступность с клавиатуры и жесты на физическом устройстве также открыты |

## Регрессия и внешние зависимости

- Есть локальные проверки миграции, JPA, ArchUnit, расчёта расстояния, гостиничного каталога, сохранения черновика и браузерного handoff. Полный зелёный прогон всех репозиториев на едином релизном наборе, отдельная проверка Excel-импорта, всех старых полей, ссылок и интеграций ещё требуются.
- Яндекс ответил на живые запросы расписания и справочника. Свой MCP Островка возвращал каталог для Москвы, Санкт-Петербурга, Казани и Сочи. Каталог подтверждает карточки объектов. Тарифы и наличие на запрошенные даты он не подтверждает. Кеширование, лимиты и реальные ответы остальных поставщиков нужно проверить в целевой среде.
- В приватном Journey реализованы изменения привязки GPS к пешеходному графу, секции рассказа, вертикальный таймлайн с положением объектов и карта скорости. Сравнение с реальными записями и мобильная приёмка остаются открытыми. Алгоритм описан в `private_jorney/docs/recorded-walk-map-matching.md`.
- До обновления публичный API тематик и пешего маршрута возвращал HTTP 200. На сервере осталось около 5,7 ГиБ после очистки. В `RESOURCE-BUDGET.md` приведён ориентир 8 ГБ плюс размер данных для сборки на сервере. Новый релиз на целевой машине пока не проверен.
